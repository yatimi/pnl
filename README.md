# pnl.

Личный дневник доходов и убытков. Быстрый ввод за день, пиксельный интерфейс, светлая и тёмная темы.

## Первая версия

- Торговый PnL по дням: сумма после комиссий и необязательная заметка.
- Отдельные записи зарплаты и других доходов. Они не влияют на торговую статистику.
- Календарь, накопленный PnL, сравнение последних 12 месяцев и список записей.
- Месячная сводка, доля прибыльных дней и максимальная просадка.
- Редактирование, подтверждение удаления, сохранение в серверной базе.
- Изолированный дневник для каждого вошедшего пользователя.
- Демо с примерами. Изменения демо временные и никогда не сохраняются в личный дневник.

Все суммы вводятся в USD и хранятся в целых центах. Конвертации валют нет. За одну дату сохраняется по одной записи каждого источника; повторное сохранение обновляет соответствующую запись. Нулевой торговый результат считается записанным днём. Процент прибыльных дней рассчитывается по дням, а не по сделкам. Просадка начинается с нулевого PnL в начале выбранного месяца. Сравнения включают неполные месяцы и пропущенные дни только в пределах введённых данных.

Сводка работает по прозрачным правилам, без генеративного AI и без прогнозов. Интеграции с биржами, мобильное приложение и настоящий AI-разбор — возможные следующие этапы.

## Разработка

React, TypeScript, Vinext и Cloudflare D1. Базовые компоненты интерфейса взяты из установленного набора. Вход в размещённую первую версию — через ChatGPT, сайт по умолчанию приватный. Перед самостоятельным размещением вне Sites нужен собственный доверенный слой аутентификации: нельзя доверять заголовкам `oai-authenticated-user-*` из открытого интернета.

Требуется Node.js 22.13+.

```sh
npm run install:ci
npm run build
```

Применить миграцию к локальной базе один раз:

```sh
node --import ./scripts/sites-env.mjs ./node_modules/wrangler/bin/wrangler.js d1 execute DB --local --config dist/server/wrangler.json --persist-to .wrangler/state --file drizzle/0000_uneven_randall.sql
npm run dev
```

Локальный dev-сервер использует тестовую личность из штатного preview-плагина. Это только режим разработки. Production не содержит обхода входа; доступ к API проверяется на сервере. Каждая операция с базой ограничена идентификатором пользователя. Личные записи не хранятся в браузере; `localStorage` используется только для темы.

Проверки:

```sh
npx tsc --noEmit
node --experimental-strip-types --test tests/journal.test.mjs
npm run build
```

Проверка API на локальном production-сервере: `python3 tests/api_smoke.py http://localhost:8787` после запуска `npm start -- --port 8787`. Скрипт создаёт изолированные тестовые записи и удаляет их после проверки.

## Ветки

- `main` — версия, соответствующая размещённому сайту.
- `develop` — интеграционная ветка.
- `feature/<name>` — отдельная задача с последующим объединением в `develop`.

Коммиты: короткое описание изменений без префиксов вроде `feat:`. Релиз переносится из `develop` в `main` после сборки и проверок.
